MedMNIST from scratch

One small network,
pointed at real medical images

Eighty lines of numpy that learned to read handwritten digits now read chest X-rays, blood smears and CT slices. The same gradient then shows what the network looks at, fools it, and is finally done without.

Try it on an X-rayReproduce the resultsSource

MNIST is the first thing anyone trains. Sixty thousand handwritten digits at 28 by 28 pixels, and a two layer network reaches 98% by the end of the afternoon. It is also where most people stop, because nothing about a digit classifier feels like it matters.

MedMNIST [1] changes that without changing the code. It is a collection of medical imaging datasets that the authors shrank to the same 28 by 28 format: chest X-rays labelled for pneumonia, breast ultrasounds labelled malignant or benign, blood smears labelled by cell type, CT slices labelled by organ. The array shapes are identical to MNIST. So the question here is simple: take the smallest network I fully understand, written by hand in numpy with the backward pass derived on paper, and see how far it goes on data where a wrong answer means something.

The dataset changes; the network does not

The network is the one from any introductory course. A 784 by 128 weight matrix, a ReLU, a 128 by n weight matrix, a softmax. Training is minibatch gradient descent with the gradients written out by hand; a finite difference test in the repository confirms they are correct. The file that defines it never mentions digits or X-rays. It takes rows and learns to map each row to a class.

I kept a small convolutional network in PyTorch as a reference, and the MedMNIST authors publish a ResNet-18 baseline at this resolution for every dataset, so there is an honest scoreboard.

The CNN is not better everywhere. On the two small binary datasets it overfits harder than the MLP does; on the two larger multi-class datasets convolution clearly pays.

Accuracy is not the number that matters

PneumoniaMNIST is 74% pneumonia. A model that says pneumonia every time scores 74%. Mine scores 82.5%, which sounds fine until the confusion matrix is written out: it catches 99.5% of pneumonia cases and clears 54% of the healthy ones. Nearly half of the healthy patients would be flagged.

The breast ultrasound model fails in the direction that matters more. It reaches 81% by calling almost everything benign and finds 40% of the malignant cases.

Try it

Sixty test X-rays, thirty of each class, shuffled. Make your own call, then see what the network said and what the label was. The second image that appears is an occlusion map: how much the network's confidence dropped when that region was hidden.

Where it looks

Because the backward pass is written out, the gradient of the loss with respect to the pixels is one extra matrix multiply. On the blood smears that gradient lands on the cell. On X-rays it does not: a fully connected network has no notion that two pixels are neighbours, so its gradient is speckled across the frame. Hiding a patch of the image and measuring the drop in confidence [7] gives a coarser but spatially coherent answer.

An attack you cannot see

The same gradient, used the other way, breaks the model. The fast gradient sign method [2] moves every pixel by a fixed step in the direction that increases the loss. At a step of 0.02, two percent of the pixel range, the image is indistinguishable from the original and the network's answer has reversed, often at higher confidence than before.

Five hospitals, no shared images

Medical images are hard to pool. Federated averaging [3] trains without pooling them. The training set is split across five simulated hospitals; each round, every hospital trains a copy of the global model on its own slice for one epoch and returns the weights, and the server averages them. Only weights travel. In numpy the averaging step is one line.

Each hospital alone trains for 20 epochs on its 942 images. The federated model sees the same images through 20 rounds of averaging and never holds more than one hospital's weights at a time. It matches the best single hospital and gets all eight images right where two hospitals do not. The shards are random and equal; real hospitals are neither, and a skewed split is the natural next experiment.

Nine in ten weights removed

Han et al. [4] showed that most trained weights can be zeroed. I remove the smallest fraction of each weight matrix by magnitude, fine tune for five epochs with the zeros held in place, and test again.

The gain at 50 to 90% on pneumonia is a regularisation effect, the territory the lottery ticket hypothesis [5] studies. A ten thousand weight network is small enough to consider for a custom accelerator.

Training without backpropagation

Every result above depends on backprop. Hinton's Forward-Forward algorithm [6] removes it. The label is written into the top left pixels of the image. Each layer is then trained on its own to be highly active on images carrying the correct label and quiet on images carrying a wrong one; activity is the mean squared output, which Hinton calls goodness. No error signal crosses between layers. To classify, write in each label in turn and keep the one that produces the most goodness.

Twenty epochs of plain SGD; Hinton reports about 1.4% MNIST error with a larger network, longer training and Adam. The point is that it works. Inference is a matmul, a ReLU and a sum of squares per layer with no backward pass, which is what makes this variant the candidate for hardware. It lives in its own file and shares nothing with the main network but the data loader.

What this establishes

A network small enough to derive on paper reaches within a few points of a published ResNet-18 on four medical datasets, and the same gradient that trains it exposes how it can be read, fooled and compressed. Two things I did not expect: the convolutional network lost to the MLP on both small binary tasks, and removing 90% of the weights improved the pneumonia model.

The results also mark the boundary. The breast model misses most malignant cases, the organ model fails on any view it was not trained on, and a two percent perturbation reverses a diagnosis. None of these is fixed by a larger network alone. The next step that matters is the skewed federated split and a proper calibration study on the pneumonia test set, whose distribution differs from its training set.

Two things that went wrong along the way

Validation accuracy on pneumonia sat at 95% while test accuracy was 82%. The two splits come from different distributions, and the model that looked finished during training was flagging half the healthy patients. Test is touched once, at the end.

The blood smear model did not train at all at first: chance accuracy, every hidden unit dead. Those images average 0.72 per pixel, so every input pushed every hidden unit the same way and the first large step zeroed the layer. Subtracting the training mean fixed it on every dataset. Half the units were dead on pneumonia too; it had simply been learning anyway.

Reproduce the experiments

Everything runs on a CPU. Datasets download on first use; the slowest script is Forward-Forward on MNIST at about four minutes. 

git clone https://github.com/Jaundel/DualMNIST
cd DualMNIST
uv sync
uv run pytest                                  # finite difference gradient check

uv run python train.py pneumoniamnist --epochs 20
uv run python explain.py pneumoniamnist        # saliency, occlusion, FGSM
uv run python shift.py
uv run python federated.py pneumoniamnist
uv run python prune.py pneumoniamnist
uv run python forward_forward.py pneumoniamnist
uv run python torch_baseline.py pneumoniamnist
uv run python figures.py                       # every figure on this page
